## 6. Lexical-only vs semantic difference (core T11.1 value, validated live)

In A2 the lexical branch produced **zero eligible candidates** — all 7 ideas scored `BELOW_RETRIEVAL_FLOOR` and retrieval stopped with `NO_ELIGIBLE_IDEAS`. Under lexical-only T11 behavior the user would have gotten nothing. The T11.1 LLM selector, given the same corpus, recalled exactly `rag-chunking` — a target with no lexical overlap with the query — as `semanticRank: 1`, with revalidation against its pinned `evaluatedVersionId` surviving. This is the central value proposition of T11.1, demonstrated against a real provider.

## 7. Judge decision and why

- A2 Judge: `{"outcome":"none","reason":"REDUNDANT_WITH_CONTEXT","dropped":[]}` — recorded as a **Judge decision**, not a semantic recall failure.
- Root cause (from the A2 transcript): the Harness agent loop's own reply already surfaced the target's content. The agent used built-in tools (`pwsh`, `glob`, `read`, `grep`) over 6 steps to explore the workspace and its parent directories, found `build/r1-home/storages/idea` with all 7 idea JSON files, read all of them, and its final assistant message presented the `rag-chunking` idea's substance. The Judge then correctly deemed resurfacing redundant with the assistant context — fail-closed silence, no claim. This is the T10 Judge working as designed.
- Environmental note for architecture review: the isolated home was laid out inside the repo tree (`build/r1-home`), so the agent could reach the idea store by walking up from the workspace. A real user's `~/.dsh` sits in a different tree from their project workspace, so this exact path is less likely there — but the interaction between the agentic assistant context and the Judge's redundancy check deserves a look, because in this Harness build **every** first message is agentic and tends to fill the assistant context with related material.

## 11. Product defects

**None found.** All observed behavior matched design: detector regex admission, lexical floor + `NO_ELIGIBLE_IDEAS` stop, llm selector single-call recall + revalidation + semanticRank, Judge fail-closed on `none`, CLAIMED-only surfacing, durable budget accounting.

Two non-defect findings are handed to architecture review:

1. **Cost model of the R1 plan was wrong, not the product**: this Harness build runs every first message as a multi-step agentic loop (6+ steps plus a provider-generated title), so a single scenario costs ~8 real requests. Any future real-provider validation must budget per agent step, not per message.
2. **Agent context vs Judge redundancy**: the agentic assistant tends to dig related material into its own reply (it read all idea JSONs here), which pushes the Judge toward `REDUNDANT_WITH_CONTEXT` and thereby suppresses resurfacing in exactly the "user vaguely remembers something" situations T11.1 targets. Worth evaluating whether Judge context should distinguish assistant-self-discovered content from resurfaced library content.
